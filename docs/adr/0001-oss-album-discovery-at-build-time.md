# ADR 0001：相册自动发现在构建时进行

- **状态**：已接受
- **日期**：2026-09-16

## 背景

相册的照片存放在阿里云 OSS 的对象存储中，按"相册根 / 相册目录 / 图片"的层级组织。
我们希望新增一个 OSS 目录后，站点能自动出现对应的相册，而不必逐个在源码里声明。

问题是这个"发现"发生在什么时机。网站是 Astro 静态站：相册列表和每个相册页都在构建时
由代码生成（相册页通过 `getStaticPaths` 枚举），构建产物是纯静态 HTML。运行期没有服务端
逻辑可以查询 OSS。

可选方案：

1. **运行期动态发现**：页面在浏览器里调用一个接口，实时向 OSS 查询目录列表再渲染。
2. **构建时发现**：构建前运行一次同步流程，把发现结果写成一个生成文件，构建时读取它。

## 决策

采用**构建时发现**。同步流程扫描相册根，为每个含图片的子目录生成照片清单，并重写一份
生成文件作为"自动发现相册"的清单；站点的相册配置把这份生成清单与手写的相册合并（同 id
时手写优先）。

## 后果

- 新增 OSS 相册后，需要重新运行同步并重新构建部署，才能反映到站点上。这是刻意接受的：
  与本站"内容变更 → 重新构建"的整体模型一致。
- 构建依赖生成文件存在。生成文件因此纳入版本控制，保证拿到仓库的人可以直接构建。
- 生成文件是人手维护配置之外的独立产物，两者不会互相覆盖；自动生成的部分重写是幂等的，
  变更 diff 可读。
- 因为不需要运行期服务端，站点可以继续部署为纯静态托管（当前为 Cloudflare/Vercel）。
- 运行期无法感知 OSS 的即时变化；这是静态站的固有限制，不是本决策引入的缺陷。
