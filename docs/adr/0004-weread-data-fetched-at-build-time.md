# ADR 0004：微信读书数据在构建时获取

- **状态**：已接受
- **日期**：2026-09-22

## 背景

微信读书模块需要展示站主的阅读情况（书架、进度、统计）。微信读书官方 Agent API
（`i.weread.qq.com/api/agent/gateway`）以 API Key 鉴权，Key 绑定用户身份，等同于账号凭据。

站点部署为 GitHub Pages 纯静态（`deploy.yml` 构建后推送到 pages 分支），运行期没有服务端。
API Key 不能出现在前端代码或构建产物里；直接从浏览器调用接口既暴露 Key，也存在跨域与
凭据滥用问题。

可选方案：

1. **浏览器实时拉取**：访客请求时经某个代理调微信读书接口。需要新增一个持有 Key 的服务端
   （如 Cloudflare Worker），改变部署形态；Key 也落在运行期服务上。
2. **构建时拉取**：构建过程中在 CI 里用环境变量中的 Key 调接口，把结果写入构建产物。

## 决策

采用**构建时拉取**，与番组计划 static 模式、OSS 相册同步（ADR 0001）同一模式。API Key
只存放在 GitHub Secrets 与本地 `.env`（不入仓库），页面数据随构建固化。

配合 GitHub Actions 定时触发（schedule）每日重建一次，阅读数据一天一更；push 新内容时
随构建自然刷新。

## 后果

- 阅读数据最多滞后一天（或距上次构建的间隔）；对"阅读情况展示"这一用途是刻意接受的。
- API Key 只存在于 CI 环境与本地开发环境，构建产物中不含 Key。
- 接口在构建期不可用时，页面回退为展示上次成功的数据或占位提示，不阻塞构建。
- 若未来想要实时数据，需要引入持有 Key 的服务端，届时重新评估本决策。
