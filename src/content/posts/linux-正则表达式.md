# 正则表达式作用

它是一种语言，用来描述我想要的字符串长什么样子。就是描述字符串模式

# 各个字符含义

## 1.普通字符

这里使用普通字符检索就是表示每行中只要包含这些普通字符就匹配。

## 2.任意一个字符:`.`

使用`.`表示任意一个字符。**注意这里只是表示一个字符**

## 3.位置匹配:`^`   `$`

`^`表示匹配行首，`$`表示匹配行尾。通常搭配起来用来匹配，完全符合中间语法的这种字符串，而不是**表示只包含中间语法的字符串**

当然也可分开使用，分别表示**匹配行首，或行尾**，注意这里*$,^都只针对一个字符*

空行：`^$`

## 4.字符集合：[]

[a-z]:表示任意一个小写字符,同理大写就表示大写字符
[0-9]:表示任意一个数字

其中范围可以连这写：[a-z0-9]

## 5.取反:^

在字符集合里面取反，**区分这个行首匹配**

[^0-9]

## 6.数量匹配：量词表示

### 1.   0或多次使用*

**作用于最近的前一个字符**



### 2.  1或多次使用+

**作用于最近的前一个字符**



### 3. 0或者1次使用？

同理



### 4.{}表示至少或者一定范围

{n,}:至少n次

{n,m}:n到m次



## 7.使用()可以打破对于单个字符的作用，对整体产生作用

(ab)+



## 8.选择：|

**区分**：`^dog|cat$`与`^(dog|cat)$`这是不同的

前者表示匹配dog开头或者cat结尾，后者表示匹配整行是cat或者dog



## 9.转义字符: `\`

想把元字符当普通字符用，就在前面加反斜杠。

- `\.` 匹配真正的点号
- `\\` 匹配反斜杠本身
- `\*` 匹配星号本身

例：匹配小数 `3.14` 必须写 `3\.14`，不转义的话 `3.14` 会把 `3a14`、`3 14` 也匹配进来。

# 在 Linux 命令中使用正则

## 10.两套方言：BRE 与 ERE

Linux 命令里的正则分两套方言，**同一个写法在两边的含义可能不同**：

- **BRE（基础正则）**：`grep`、`sed` 默认使用。`+ ? | ( ) { }` 不当元字符，想用必须转义：`\+` `\?` `\|` `\(` `\)` `\{n\}`
- **ERE（扩展正则）**：`grep -E`（等价 `egrep`）、`sed -E`、`awk` 默认使用。元字符直接写，不用转义

例：匹配一个或多个 o

```bash
grep 'go\+d' file      # BRE：+ 要转义
grep -E 'go+d' file    # ERE：直接写
```

**建议：习惯统一加 `-E` 用 ERE，能少踩一大半转义坑。**

## 11.POSIX 字符类

在 `[]` 里面还可以用 POSIX 字符类，比手写范围更可读：

- `[[:digit:]]`：数字，等价 `[0-9]`
- `[[:alpha:]]`：字母
- `[[:alnum:]]`：字母 + 数字
- `[[:space:]]`：空白字符（空格、Tab）
- `[[:upper:]]` / `[[:lower:]]`：大写 / 小写字母

例：匹配"只由空白组成的行"（比单纯的 `^$` 覆盖更全）

```bash
grep -E '^[[:space:]]*$' file
```

## 12.grep 实用选项

格式：`grep [选项] '正则' 文件`

- `-i`：忽略大小写
- `-n`：显示行号
- `-v`：反选，输出**不**匹配的行
- `-c`：只统计匹配的行数
- `-o`：只输出匹配到的部分（默认输出整行）
- `-r`：递归搜索目录
- `-w`：整词匹配，`grep -w dog` 不会匹配 dogcat
- `-l`：只列出包含匹配的文件名
- `-A 2` / `-B 2` / `-C 2`：显示匹配行后 2 行 / 前 2 行 / 前后各 2 行

```bash
# 递归找当前目录所有 py 文件里的 TODO
grep -rn 'TODO' --include='*.py' .
```

## 13.sed：用正则做替换

格式：`sed [-E] 's/正则/替换内容/标志' 文件`

- 替换内容里 `&` 代表正则整个匹配到的内容
- `\1` `\2` 引用正则里的第 1、2 个分组
- 标志 `g`：替换行内所有匹配（默认只替换每行第一处）

```bash
# 把 2024 全部换成 2026
sed -E 's/2024/2026/g' a.txt

# 交换两列：zhang san → san zhang
sed -E 's/([a-z]+) ([a-z]+)/\2 \1/' names.txt

# 删除注释行和空行（看配置文件常用）
sed -E '/^#|^$/d' nginx.conf
```

注意：sed 默认只输出修改结果，**加 `-i` 才真正写入文件**（`-i.bak` 会先备份再改）。

## 14.awk：正则筛选 + 按列处理

awk 的模式部分用的就是 ERE，配合列处理很强大：

```bash
# 输出以 error 开头行的第 2 列（默认按空白切列）
awk '/^error/ {print $2}' app.log

# $0 整行，$1 $2 ... 第 1、2 ... 列；-F: 指定冒号为分隔符
awk -F: '/^root/ {print $7}' /etc/passwd
```

## 15.实战例子

```bash
# 1. 提取日志里的 IPv4 地址
grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' access.log

# 2. 匹配 11 位手机号（整行）
grep -E '^1[3-9][0-9]{9}$' phones.txt

# 3. 提取邮箱
grep -Eo '[a-zA-Z0-9._%+-]+@[a-zA-Z0-9.-]+\.[a-z]{2,}' users.txt

# 4. 去掉配置文件里的注释行和空行
grep -Ev '^\s*(#|$)' /etc/ssh/sshd_config

# 5. 统计文本里出现最多的单词 TOP5
grep -Eo '[a-z]+' article.txt | sort | uniq -c | sort -rn | head -5
```

## 16.命令行里的常见坑

### 1.正则的 `*` 不是通配符

Shell 里的 `*.txt` 是**通配符（glob）**，匹配任意文件名；正则里的 `a*` 是量词，表示"0 个或多个 a"。两者长得像但完全是两回事。

### 2.正则记得用引号包起来

`grep ^dog$ file` 里的 `$`、空格可能被 shell 提前解释，正确写法是 `grep '^dog$' file`。习惯：正则一律套单引号。

### 3.默认是贪婪匹配

量词总是"能匹配多长就多长"：`grep -Eo '<.+>'` 遇到 `<a> b <c>` 会整段匹配下来，而不是分别得到 `<a>` 和 `<c>`。最短匹配要用懒惰量词 `.+?`，但那是 PCRE 语法，得用 `grep -P '<.+?>'`。

### 4.单引号字符串里没法再放单引号

想匹配的内容里有 `'`，要么用 `'\''` 拼接，要么换双引号——但双引号里 `$` 会被 shell 展开，要小心。
